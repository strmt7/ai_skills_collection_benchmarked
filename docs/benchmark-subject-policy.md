# Controlled benchmark subjects

The owner approved this narrow exception for measuring coding-agent behavior.
It does not establish that an experiment or execution boundary is qualified.

Use one development controller. Benchmark subjects are serial, isolated
experimental conditions, never delegated developers or reviewers. Do not use
collaboration agents or parallel model trials.

For a valid no-skills baseline, subjects must not discover this collection's
AGENTS.md, host skills, memory or development context. Freeze identical task
inputs, model settings, ordinary agent tools, budgets and environment across
conditions; vary only the declared intervention. The controller continues to
use all three mandatory tools and retain their receipts. Intentional
instruction/tool ablations are allowed only inside declared subject conditions;
this grants no general bypass.

Runner/grader integration and execution/collection isolation qualification are
permitted for these trials. Preserve the launch refusal until the actual
complete boundary passes independently specified positive and negative
controls. Do not substitute a host subprocess or unqualified alternate launcher.
Security-scanner, code-scanning-alert and history-scan remediation remain paused.
The owner's subsequent dependency-maintenance instruction permits package and
tool updates and Dependabot remediation. Qualify complete compatible graphs,
retain failure evidence and preserve immutable upstream mirrors. This does not
authorize alert suppression or relax the separate model-launch qualification.

Begin with public, development-exposed tasks to qualify infrastructure and
calibrate difficulty. Task contracts and evaluators must be independent of
candidate skill text. Do not retrieve benchmark solutions or select tasks for
the largest observed candidate gains. Preserve every attempt, setup failure,
timeout, negative effect and missing measurement. Do not invoke a model before
qualification or access holdouts before freezing the candidate and confirmatory
selection, sample size, thresholds and analysis.

Use fresh workspaces, separate hidden grading material, explicit resource,
output and time limits, job-owned process cleanup and only the required model
endpoint. Record requested and provider-resolved identities separately. Do not
copy credentials into fixtures or logs, access personal profiles, start
persistent services or modify other user repositories. External public
repositories are disposable benchmark inputs only.

Publish on main through the authenticated GitHub connector. Subjects cannot
publish repository changes. Keep the release/tag hold. Report gains only for
the tested models, tasks and environments; this exception establishes no
efficacy result or commercial readiness.
