# Testing category boundaries

Read both complete single-file packages: Composio's `qa-response` and the existing
owner-source `verification-loop` mirror. They are materially different from test
runner or coding-agent benchmark skills. Resource-level records retain their
exact source identities; these text reviews do not establish runtime efficacy.

The QA response checklist covers useful accuracy, completeness, tone and clarity
checks. However, it supplies no product/source context or independent method to
verify factual claims. Its numeric score has no anchored rubric, examples or
inter-reviewer calibration. “Any claims factually correct?” should evaluate all
material claims, and required greetings/sign-offs depend on channel and context.
The embedded verdict is an editorial disposition, not a measured coding-agent
benchmark result. `$ARGUMENTS` and manual invocation fields depend on the host's
skill loader. Review drafted replies without sending or making commitments unless
the human has explicitly authorized that action. Final category routing should
place this package with communication/support and retain an auditable migration.

The existing owner-source verification mirror asks for targeted tests, broad
verification for broad changes and exact outcomes. It has no supporting scripts
or frontmatter, and its CI path/Python command requirement depends on the origin
repository. Its “tests for any new branch” rule should prioritize meaningful
observable regression checks rather than tests that mirror syntax. Branch
coverage is evidence about execution; it does not establish an independent
correctness oracle. The original source can remain an existing project reference,
but no new overlay will name that owner repository or reproduce its private
configuration. The general `verification-loop-current` overlay supplies reusable
guidance without changing this immutable project reference.

Both reviews remain in progress pending loader/source-refresh qualification and
an explicit final routing disposition. Their applicability must be recorded
before designing independent benchmark tasks; a universal coding score across
every catalog entry would conflate unlike purposes.
