# Spreadsheet recalculation component review

The pinned [Anthropic XLSX skill](../included/skills/by-category/documents-spreadsheets-presentations/official-reference/xlsx-anthropics/SKILL.md) and [scientific XLSX skill](../included/skills/by-category/science-research-data-analysis/latest-release-community/xlsx-scientific-agent-skills/SKILL.md) contain byte-identical copies of a helper for recalculating workbooks and reporting errors. In source-bound controls using openpyxl 3.1.5, a simulated office process and temporary workbooks, the pinned helper reported success after a simulated timeout while a formula still had no cached value. It also printed an error for a missing workbook while its command-line process exited with code 0. The examined newer upstream helper reported an error and used a nonzero exit code for those respective cases.

Both versions reported an error for an ordinary text cell containing `#N/A`; an actual `#DIV/0!` error cell was also correctly reported in the control. Check both the process result and workbook values independently, and distinguish actual error cells from text before relying on this helper's output.

The [reproducer](../artifacts/research/2026-10-30/xlsx-recalculation/reproduce.py) verifies exact source hashes, compares the mirror and pinned upstream syntax trees, and runs six cases against each of three versions. [Windows](../artifacts/research/2026-10-30/xlsx-recalculation/windows-result.json) and [Linux](../artifacts/research/2026-10-30/xlsx-recalculation/linux-result.json) produced identical case outcomes. A separate [Windows run](../artifacts/research/2026-10-30/xlsx-recalculation/scientific-windows-result.json) using the scientific mirror matched them. The simulated timeout used the Linux exit code 124 on both platforms; it does not establish Windows timeout behavior. The subprocess for the missing-file CLI case was real Python, with the office module simulated. In these simulated controls, no LibreOffice process, actual recalculation, profile interaction, full skill task or agent benchmark was run.

On the tested Windows host, the pinned and newer office helpers both raise an `AttributeError` when `socket.AF_UNIX` is absent. The [environment control](../artifacts/research/2026-10-30/xlsx-recalculation/windows-office-env-control.py) reproduced this with Windows Python 3.11.9, 3.12.10, 3.13.17 and 3.14.8; [recorded results](../artifacts/research/2026-10-30/xlsx-recalculation/office-env-windows-3.13.json) include the exact helper hashes. A separate [startup reproducer](../artifacts/research/2026-10-30/xlsx-recalculation/startup-reproduce.py) executed the pinned and newer scripts as real Python subprocesses using disposable workbooks and an isolated profile directory with Python 3.13.17. The [Anthropic](../artifacts/research/2026-10-30/xlsx-recalculation/startup-windows-3.13-result.json) and [scientific](../artifacts/research/2026-10-30/xlsx-recalculation/startup-scientific-windows-3.13-result.json) mirrors behaved identically: both scripts exited with an error before launching LibreOffice and the formula remained uncached. The installed LibreOffice was available on the process path, but the failure prevents an end-to-end recalculation claim.

For reproduction, install openpyxl 3.1.5 in an isolated Python environment, save the exact [pinned](https://github.com/anthropics/skills/blob/2c7ec5e78b8e5d43ea02e90bb8826f6b9f147b0c/skills/xlsx/scripts/recalc.py) and [observed newer](https://github.com/anthropics/skills/blob/ca45fc496a3436251f191354091d557da31c15b5/skills/xlsx/scripts/recalc.py) files, and pass their paths with `--pinned` and `--current` and the local mirrored helper path with `--mirror`. The control rejects changed source bytes. For the startup control, also provide the mirrored and [newer office helper](https://github.com/anthropics/skills/blob/ca45fc496a3436251f191354091d557da31c15b5/skills/xlsx/scripts/office/soffice.py) via its `--pinned-office` and `--current-office` options. The [source evidence](../artifacts/research/2026-10-30/xlsx-recalculation/source-evidence.json) records file and API-capture identities. The mirror and pinned source differ in formatting but have matching Python syntax trees and case outcomes.

The observed newer script is only one part of the upstream skill; this review neither qualifies a full upstream update nor proves end-to-end spreadsheet correctness. The source lock and mirror remain unchanged.
