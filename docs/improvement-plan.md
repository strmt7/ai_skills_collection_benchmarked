# Release readiness

This collection remains experimental. Its catalog, tested references and
evaluation tools are available for inspection, but commercial readiness and a
meaningful advantage over default coding agents have not been established.

Use [the documentation index](README.md) to choose and try a skill. The
[results](benchmark-results.md) explain recorded measurements. Current work is
tracked for every skill in the [improvement ledger](../data/improvement_ledger.json);
resource review, revision and evaluation are separate phases.

| Release requirement | Evidence needed |
| --- | --- |
| Current, traceable sources | Verified stable releases or explicit default-branch policy, immutable source locks and licence notices |
| Complete skill research | Every skill and bundled resource reviewed in bounded categories, with recorded findings and remaining work |
| Qualified maintained guidance | Original mirrors preserved; explicit overlays tested against independent API/application contracts |
| Meaningful agent benefit | Independently authored tasks and evaluators, matched model settings/budgets, held-out trials and uncertainty estimates against default and Karpathy baselines |
| Honest presentation | Coverage, static checks, excerpt controls and model trials labelled separately; no fabricated or selectively omitted failures |
| Secure delivery | Dependency and code-scanning findings remediated where possible, fresh alert and PR audits, source-bound verification and no suppression to create a pass |
| Portable setup within supported systems | Explicit runtimes and provider paths, isolated installs, mandatory tool receipts and qualification on documented systems |
| User documentation | Installation, choosing/loading skills, interpreting results and troubleshooting first; contributor material linked separately |
| Final layout and README | Simplified files and folders only after the research/evaluation work; working migrations, links and regenerated metadata |

Selected [frontend](research-frontend-contracts.md) and
[API/backend](research-backend-contracts.md) controls already reproduce concrete
source defects and qualify maintained examples. They do not satisfy the agent
benefit requirement. CI retains actual observations and
[Python tooling coverage](coverage.md); neither replaces those trials.

Owner repositories are read-only references for general requirements and quality
control. Maintained skills remain independent of their names and installations.
The earlier two-hour restriction has expired; access boundaries and each
repository's instructions still apply.

Historical progress checkpoints are available in
[the previous published plan](https://github.com/strmt7/ai_skills_collection_benchmarked/blob/b23eeb5ac16a4455b027cd4c8da068fc97fee3a6/docs/improvement-plan.md).
Frozen benchmark evidence, source notices and failed-run records stay in their
original locations. Historical counts are not current release status.
